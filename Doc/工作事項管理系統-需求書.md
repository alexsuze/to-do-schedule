# 工作事項管理系統 需求書

- 版本：v1.4（v1.0～v1.3 已上線；v1.4 新增第 12 節「公司」，使用者已確認；第一步、第二步皆已上線並測試通過）
- 使用者：單人
- 核心概念：**任務紀錄 + 工時紀錄**。任務以卡片管理；把卡片拖進每 30 分鐘一格的週時程表，排在表上的時段就是工時。

標「暫定」的項目是使用者沒特別指定、先採最簡單做法的部分，確認後拿掉標記。

---

## 1. 頁面總覽

| 頁面 | 用途 |
|------|------|
| 任務 | 建立、編輯、完成任務卡 |
| 時程表 | 週檢視，把任務拖進時段、拉長縮短調整工時 |
| 統計 | 工時、完成狀況、分類統計 |
| 回收桶 | 已刪除的任務，可還原或永久刪除 |
| 設定 | 分類管理、Email 摘要設定 |

左側選單切換頁面。

**深色 / 淺色模式**：頁面上方有切換按鈕，可在深色、淺色之間切換，所有頁面一起套用。選擇記在瀏覽器裡，下次打開維持；第一次打開時跟隨電腦系統的設定。

## 2. 任務卡

### 2.1 欄位
| 欄位 | 必填 | 說明 |
|------|------|------|
| 標題 | 是 | 1～100 字 |
| 描述 | 否 | 多行文字 |
| 分類 | 否 | 從設定的分類中選一個（2.3），卡片顯示分類顏色 |
| 死線 | 否 | 日期 + 時間；只選日期時預設 18:00 |
| 子任務 | 否 | 多筆「checkbox + 名稱」，可新增、勾選、改名、刪除、拖曳排序 |
| 狀態 | — | 未完成 / 完成，新建預設未完成 |

### 2.2 任務頁
- 以卡片排列顯示，每張卡片顯示：標題、分類色、死線、子任務進度（例如 2/5）、累計工時（例如 3.5h）。
- 死線提示：24 小時內到期顯示警示色，已逾期顯示紅色。
- 切換「未完成 / 已完成 / 全部」；預設只看未完成。
- 排序：死線近的在前，沒死線的在後。
- 點卡片開編輯視窗；卡片上可直接勾選完成。
- 刪除：需確認，刪除後移到回收桶（見 2.4）。

### 2.3 分類
- 在設定頁管理：新增、改名、改顏色、刪除。
- 刪除分類時，屬於該分類的任務變成「未分類」，不會刪除任務。

### 2.4 回收桶
- 刪除的任務進回收桶；在回收桶期間，它的時段**不顯示在時程表、不計入統計、不佔用時間**（其他任務可以排進那段時間）。
- **還原**：任務回到任務頁，時段一起回到時程表。若某個時段在刪除期間已被其他任務佔用，該時段不還原並提示。
- **永久刪除**：可單筆刪除或「清空回收桶」，需確認；任務與它的時段一起刪除，無法復原。
- **自動清除**：進回收桶滿 30 天自動永久刪除，每天凌晨 03:00 執行。
- 回收桶列表顯示：標題、分類、刪除時間、剩幾天會被自動刪除。

## 3. 時程表

### 3.1 版面
- 週檢視：橫向 7 天（週一～週日），直向每 30 分鐘一格。
- 可切換上週 / 下週，「本週」按鈕回到這週；今天那一欄標示底色，並顯示目前時間線。
- 時段範圍：整天 00:00～24:00，**預設只展開 09:00～18:00**；上下兩端各有「展開更早 / 展開更晚」按鈕，點一下顯示前後其他時段。展開狀態記在瀏覽器裡，下次打開維持。每次展開 3 小時。
- 左側列出**未完成**的任務卡（小卡），可搜尋標題。有填開始時間的任務，只在**開始時間早於該週結束（週日 24:00）**的週才列出；沒填視為已開始。看往後的週（那週週一在現在之後）時，**死線早於那週週一的任務不列**；本週與過去的週照常列出，逾期的任務仍可補排（2026-11-13 使用者選 A）。已排的時段不受影響，也可以排在開始時間之前。
- 標示台灣國定假日與補班日（日期下方標籤＋放假日與週末整欄底色，補班日不上色），資料取自行政院人事行政總處辦公日曆的公開整理檔，讀不到時不標示。

### 3.2 操作
- **放入**：從左側把任務卡拖進格子，建立一個時段，預設 0.5 小時（1 格）。
- **調整工時**：拖曳時段的下緣延長或縮短，以 30 分鐘為單位，最短 30 分鐘。
- **移動**：拖曳時段本身換到其他時間或其他天。
- **刪除**：拖曳時段時畫面下方出現垃圾桶區，拖進去即移除（只刪時段，不刪任務）；移除後提示可「復原」。
- **同一任務可放很多次**，任務的累計工時 = 所有時段加總。
- 時段顯示任務標題與分類色；點時段開該任務的編輯視窗。
- 時段不可跨日（最晚到 24:00）。
- 時段不可重疊：放到已被佔用的時間會被擋下並提示（一個人同一時間只做一件事，統計才不會重複算）。
- 已完成任務的時段仍留在時程表上（顯示淡色），並計入統計。

### 3.3 工時意義
時段**不區分預計和實際**：先排程，實際有變動就拖曳調整，最後留在表上的就是工時。

## 4. 統計頁

- 期間選擇：本週 / 本月 / 自訂起訖日期。
- **工時總計**：期間內總工時、平均每天工時（總工時 ÷ 有排工時的天數，沒排的日子不算）；每天工時長條圖。
- **分類統計**：各分類工時佔比圓餅圖（含「未分類」），加上各分類小時數。
- **完成狀況**：未完成數、已完成數、逾期數（未完成且已過死線）、期間內完成數。
- 工時以時段的實際時間計算，例如 2 個時段各 1.5 小時 = 3 小時。

## 5. Email 每日摘要

- 每天固定時間寄一封摘要信，內容：
  - 今天到期的任務
  - 已逾期的任務
  - 今天時程表上排了哪些時段（時間 + 任務名）
  - 本週累計工時：週一到昨天（已經過去的天數）的工時加總，例如週三寄信只算週一＋週二；沒有工時（含週一）就不列此項。此項不影響「要不要寄」
- 三項都沒有內容時不寄。
- 設定頁：收件 Email、寄送時間（預設 08:00）、開 / 關、寄送測試信。
- 時區固定 Asia/Taipei。
- 寄件者 `onboarding@resend.dev`，只能寄到 Resend 帳號的 Email。

## 9. 多人使用（v1.1）

### 9.1 決策（2026-10-28 使用者已選）
| 項目 | 決定 |
|------|------|
| 使用方式 | **各用各的**：每人資料完全獨立、彼此看不到（不做團隊共用） |
| 登入方式 | **Google 登入**（不設密碼，無忘記密碼問題） |
| 註冊門檻 | **管理員核准**：任何人可用 Google 申請，管理員核准後才能使用 |
| 寄信網域 | **先不買**：Resend 測試寄件者只能寄到管理員自己的 Email，其他使用者暫不提供每日摘要 |

### 9.2 帳號與登入
- 登入頁只有「用 Google 登入」按鈕。
- 第一次用 Google 登入即建立帳號，狀態為「待核准」，畫面顯示「已送出申請，等待管理員核准」。
- 管理員：以環境變數 `ADMIN_EMAIL` 指定的 Google 帳號，第一次登入自動成為已核准的管理員。
- 登入成功後由後端發一張自己的通行證（有效 30 天），存在瀏覽器；每次呼叫 API 都帶上。過期或被停用 → 回到登入頁。
- 登出：清除瀏覽器裡的通行證。
- 側邊欄下方顯示目前帳號（Google 大頭貼＋名稱）與登出。

### 9.3 管理員頁（只有管理員看得到）
- 使用者列表：大頭貼、名稱、Email、狀態（待核准 / 使用中 / 已停用）、申請時間、最後登入時間。
- 操作：核准、停用、重新啟用。停用的人無法登入，資料保留。
- 有新的待核准申請時，側邊欄「管理」旁顯示數字。
- 有人**第一次**申請時寄信到 `ADMIN_EMAIL`：主旨「[待審核] 名稱（Email）申請使用工作事項管理」，內容含名稱、Email、申請時間與「前往管理頁審核」連結（`#/admin`）；待核准期間重複登入不重寄；寄信失敗不影響申請。
- 未登入時打開站內連結（例如信中的管理頁連結）會先到登入頁，登入後自動回到原本的頁面。
- 刪除使用者（連同資料）：暫不做，需要時再加。

### 9.4 資料隔離
- `tasks`、`categories`、`time_blocks` 加 `user_id`；`settings` 改為每人一筆（`_id` = 使用者 id）。
- 所有查詢、新增、修改、刪除都只限自己的資料；拿別人的 id 操作一律視為「找不到」。
- 時段「不可重疊」只檢查自己的時段。
- 回收桶 30 天自動清除、每日摘要排程：對所有使用者各自處理。
- 國定假日資料大家共用（本來就在瀏覽器端讀取）。

### 9.5 既有資料
- 上線後管理員第一次登入時，現有所有任務、分類、時段、設定自動歸到管理員帳號，不會遺失。

### 9.6 每日摘要
- 收件人固定為帳號的 Google Email（不再另外填）。
- 未購買網域前只有管理員可開啟；其他人的設定頁顯示「每日摘要目前僅限管理員」。之後買網域只需改環境變數即可全面開放。

### 9.7 安全
- 拿掉原本寫在前端程式裡的共用 API Token（`X-API-Token`），改為每人登入後的通行證。
- 後端驗證 Google 回傳的身分憑證（確認是 Google 簽發、發給本系統、未過期）。
- 未核准、已停用的帳號呼叫任何 API 都會被拒絕。

### 9.8 需要使用者協助的設定（開發時會一步一步帶）
1. Google Cloud Console 建立專案與「OAuth 用戶端 ID」（類型：網頁應用程式），允許的來源填 `https://alexsuze.github.io` 與 `http://localhost:5173`；同意畫面發布為「正式版」（只用基本的 Email / 名稱權限，不需 Google 審查）。
2. 把用戶端 ID 填到 GitHub Secrets（`VITE_GOOGLE_CLIENT_ID`）與 Railway（`GOOGLE_CLIENT_ID`）。
3. Railway 新增 `ADMIN_EMAIL`（你的 Google Email）與 `JWT_SECRET`（通行證簽章用的隨機字串，我會產生）；`API_TOKEN` 可移除。

### 9.9 開發階段
1. **後端帳號與資料隔離**：users、Google 登入驗證、通行證、所有資料加 `user_id`、舊資料歸給管理員
2. **前端登入**：登入頁、待核准頁、登入狀態與登出、未登入導向登入頁
3. **管理員頁**：核准 / 停用使用者
4. **每日摘要改為每人一份**（目前僅管理員可用）

每個階段完成就上線，由使用者實際操作驗證。第 1、2 階段需同時上線（後端改用通行證後，舊前端將無法使用）。

## 10. 專案（v1.2）

### 10.1 決策（2026-10-29 使用者已選）
| 項目 | 決定 |
|------|------|
| 結構 | **專案 → 分類 → 任務**：每個專案有自己的分類（不同專案的分類互不共用） |
| 專案必填 | **可以不選**：沒選的任務歸在「無專案」，統計時單獨列出 |
| 舊資料 | **全部放進一個預設專案「一般」**，使用者再自行建立專案並把分類移過去 |
| 時程表顏色 | **依專案**：時段用專案顏色；分類顏色用在任務卡標籤 |
| 工時統計主體 | 專案 |

### 10.2 專案管理（設定頁）
- 新增、改名、改顏色（同分類色盤 16 色）、拖曳排序。
- **封存**：做完的專案可封存。封存後新增 / 編輯任務的選單不再出現、篩選預設不顯示，但歷史工時保留，統計頁仍可查；可隨時取消封存。
- **刪除**：需確認；專案底下的分類一併刪除，任務保留並改為「無專案、未分類」（工時仍在，歸到「無專案」）。建議用封存代替刪除。
- 分類管理改為「依專案分組」顯示；每個分類可**移到其他專案**（該分類的任務會跟著移過去）。

### 10.3 任務
- 編輯視窗先選專案、再選分類；分類選單只列出該專案的分類。換專案時若原分類不屬於新專案，分類清空。
- 選了分類就一定屬於該分類的專案（後端檢查）。
- 任務卡標籤顯示「專案 / 分類」，例如「樂天 / KM」；只有專案時顯示專案；都沒有顯示「無專案」。
- 任務頁、時程表左側清單新增「專案」篩選（預設全部、不含已封存）。

### 10.4 時程表
- 時段顏色改為所屬任務的**專案顏色**；無專案為灰色。
- 時段提示文字加上專案名稱。

### 10.5 統計頁
- 上方新增專案切換：「全部專案」或任一專案（含已封存，封存的標註「已封存」）。
- **全部專案**：工時總計、每天 / 每週工時長條圖、**各專案工時佔比**（圓餅圖＋圖例，含「無專案」）、完成狀況。
- **單一專案**：該專案的工時總計、每天 / 每週工時、**專案內各分類工時佔比**（含「未分類」）、**各任務工時排行表**（任務名稱、分類、工時、佔比、是否完成）、該專案的完成 / 未完成 / 逾期數。
- 期間切換（本週 / 本月 / 自訂）維持不變，與專案切換可同時使用。

### 10.6 資料結構
- 新增 `projects`：`user_id`、`name`（1～30 字）、`color`、`order`、`archived`（boolean）。
- `categories` 新增 `project_id`（必填）。
- `tasks` 新增 `project_id`（可為 null＝無專案）；有 `category_id` 時 `project_id` 必須等於該分類的專案。
- 舊資料搬移：每位使用者若有未掛專案的分類，自動建立專案「一般」並把這些分類掛上；有分類的任務 `project_id` 設為「一般」，沒分類的任務維持無專案。搬移可重複執行、不會重複建立。

### 10.7 不做（需要時再加）
- 專案預估工時與進度條
- 每日摘要信依專案拆分工時
- 匯出專案工時報表（CSV / Excel）
- 跨專案共用分類


## 11. 未開始任務開關與已完成任務封存（v1.3）

### 11.1 決策（2026-11-02 使用者已選）
| 項目 | 決定 |
|------|------|
| 未開始開關預設 | 顯示（與原本相同） |
| 封存天數 | 每人在設定頁選 7 / 14 / 30 / 60 / 90 天，預設 14 天 |
| 改天數 | 立即套用到所有已完成任務 |
| 立即封存 | 已完成的任務卡上有「立即封存」按鈕 |

### 11.2 任務頁
- 「顯示未開始」開關：關閉時隱藏開始時間還沒到的任務，標題列顯示「已隱藏 N 個未開始」。選擇記在這台電腦。

- 已完成卡片有「立即封存」按鈕，封存後提示可「復原」。

### 11.3 封存規則
- 已完成任務，從「完成時間」與「最後一次解除封存時間」較晚者起算，滿設定天數即視為封存（不需排程，打開頁面時判斷）。
- 解除封存：回到任務頁「已完成」，重新計算天數；**不改動完成時間**（統計「本期完成」不受影響）。
- 封存的任務改回未完成 → 自動解除封存。
- 封存不會自動刪除；封存頁點開任務仍可編輯或移到回收桶。回收桶還原後依規則回到封存或任務頁。
- 封存只影響任務頁顯示：時程表時段、統計、每日摘要照常計算。
- 上線時，完成超過設定天數的舊任務會一次進入封存。

### 11.4 封存頁（側邊欄「封存」）
- 列表顯示：標題、專案 / 分類、完成時間、累計工時、「解除封存」按鈕；依完成時間新到舊。
- 可搜尋標題、依專案篩選；點一列開啟任務編輯視窗。

### 11.5 API
- `POST /api/tasks/{id}/archive`（只限已完成）、`POST /api/tasks/{id}/unarchive`，回傳任務。
- `GET /api/settings` 多回傳 `archive_days`；`PUT /api/settings/archive-days`（`{ days }`）。

### 11.6 不做（需要時再加）
- 封存頁分頁 / 後端篩選（任務累積到幾千筆再做）
- 批次解除封存


## 12. 公司（v1.4）

最上層加「公司」：**公司 → 專案 → 分類 → 任務**。每家公司的任務、時程表、統計分開看；不同公司可以排在同一個時段，同一家公司不行。

畫面示意圖（使用者已確認，2026-11-12）：https://claude.ai/artifact/H8PobxRK7Ppo66R79iKx7J

### 12.1 決策（2026-11-12 使用者已選）
| 項目 | 決定 |
|------|------|
| 公司的用途 | **自己分類用**：資料一樣只有自己看得到，不是團隊共用 |
| 任務歸屬 | 每個任務**一定屬於一家公司**；專案仍可不選（每家公司有自己的「無專案」） |
| 舊資料 | 自動建立公司「我的公司」，現有專案、分類、任務、時段全部放進去，使用者再自行改名 |
| 專案換公司 | **可以**：底下的分類、任務、時段跟著搬；搬過去會撞到新公司的時段時擋下，並列出撞到哪幾段 |
| 公司管理 | 改名、顏色、拖曳排序、封存；**不做刪除** |
| 切換位置 | 側邊欄最上方「目前公司」按鈕；每台電腦記住上次選的公司 |
| 全部公司 | 只有**任務頁**可選「全部公司」；時程表、統計只能看單一公司 |
| 其他公司的時段 | 時程表上以**灰色斜線虛框「X 公司忙碌」**顯示，只是提醒，不能點、不擋排程 |
| 設定 / 封存 / 回收桶 | 只顯示目前公司的內容；外觀、提醒、封存天數等個人設定所有公司共用 |
| 工作開始前提醒 | 所有公司的時段都提醒（不管目前切到哪家），通知標題加公司名 |
| 每日摘要 | **一封信，依公司分段**；本週累計工時也依公司分列 |

### 12.2 公司切換
- 側邊欄最上方「目前公司」按鈕（顯示公司顏色方塊＋第一個字＋名稱），點開選單：
  - 各公司（未封存的）：名稱、未完成任務數，目前公司打勾。
  - 「全部公司」：只有任務頁可選；在其他頁面顯示為灰色並註明「只有任務頁可用」。
  - 「新增 / 管理公司」：前往設定頁。
- 側邊欄收合時：只顯示公司顏色方塊與第一個字，滑鼠移過去顯示全名，點了一樣打開選單。
- 手機：上方標題列右邊放公司按鈕，不用打開側邊欄就能切換。
- 選擇記在這台電腦（localStorage，名稱加專案前綴 `to-do-schedule:`）。在任務頁選「全部公司」後切到時程表 / 統計，改用最後一次選的單一公司。
- 目前公司被封存、或記住的公司已不存在時，自動切到排序第一家未封存的公司。

### 12.3 公司管理（設定頁）
- 新增、改名（1～30 字）、改顏色（同專案色盤 16 色）、拖曳排序。
- **封存**：不出現在切換選單；資料保留，取消封存後恢復。至少要留一家未封存的公司（最後一家不能封存）。
- 設定頁的「專案管理」「分類管理」只列出目前公司的；每個專案可**移到其他公司**（規則見 12.1，撞到時段時擋下）。

### 12.4 任務
- 新增任務自動放在目前公司；在任務頁「全部公司」時，新增視窗需先選公司。
- 編輯視窗最上面加「公司」選單（2026-11-12 使用者確認）：換公司時專案、分類清空；任務有時段且會撞到新公司的時段時擋下並提示。
- 任務頁「全部公司」時：卡片標籤加上公司名（「公司 / 專案 / 分類」），專案篩選依公司分組。
- 封存頁、回收桶只列出目前公司的任務。回收桶還原時，時段只跟**同公司**的時段比對是否被佔用。

### 12.5 時程表
- 左側任務清單、格子裡的時段、「本週已排」工時都只算目前公司。
- **重疊規則**：同一家公司的時段不能重疊（跟現在一樣，變紅擋下）；不同公司可以重疊。
- 其他公司的時段畫成灰色斜線虛框，右下角標「X 公司忙碌」，滑鼠移過去顯示「X 公司已排 09:00–10:00（不同公司可以重疊，只是提醒）」。不能點、不能拖。
- 自己的時段若和其他公司的時段重疊，右邊留一條空隙露出後面的斜線，讓人看得出那段也有別的安排。

### 12.6 統計頁
- 只算目前公司。上方專案切換的「全部專案」＝這家公司的全部專案（含這家公司的「無專案」）。
- 期間切換、專案切換、各圖表規則不變。

### 12.7 提醒與每日摘要
- 工作開始前提醒：所有公司的時段都會提醒，標題「〔A 公司〕【專案】任務 即將開始」；同時段兩家都有排時跳兩則。
- 每日摘要：一封信，內容依公司分段（每段列今天到期、已逾期、今天的時段、本週累計工時）；沒有內容的公司不列。主旨的數字為所有公司合計。

### 12.8 資料結構
- 新增 `companies`：`user_id`、`name`（1～30 字）、`color`、`order`、`archived`（boolean）。
- `projects` 新增 `company_id`（必填）。
- `tasks` 新增 `company_id`（必填）；有 `project_id` 時 `company_id` 必須等於該專案的公司（後端檢查）。
- `time_blocks` 不加欄位：公司以所屬任務判斷。
- 舊資料搬移：每位使用者若有未掛公司的專案或任務，自動建立公司「我的公司」並全部掛上。搬移可重複執行、不會重複建立；新使用者第一次登入也自動建立一家「我的公司」。

### 12.9 API
- `GET/POST /api/companies`、`PUT /api/companies/{id}`（改名、顏色、封存）、`PUT /api/companies/reorder`（`{ ids }`）。
- `PUT /api/projects/reorder`、`PUT /api/categories/reorder` 改為只送目前公司的 id（其他公司的順序不動）。
- `DELETE /api/trash?company_id=…`：只清空這家公司的回收桶。
- `PUT /api/projects/{id}` 可帶 `company_id`＝移到其他公司；撞到時段回 409，訊息列出撞到的時段。
- 任務新增 / 編輯帶 `company_id`；換公司撞到時段回 409。
- 現有列表 API 維持回傳自己的全部資料，由前端依目前公司篩選（ponytail：資料量大再加公司參數）。

### 12.10 開發階段
1. **第一步**：公司資料結構、舊資料搬移、設定頁公司管理、側邊欄切換、任務頁、時程表（重疊規則＋其他公司忙碌）、封存頁、回收桶。
2. **第二步**：統計頁、每日摘要依公司分段、提醒加公司名。

每一步完成就上線，由使用者實際操作驗證。

### 12.11 不做（需要時再加）
- 刪除公司（用封存代替）
- 公司給多人共用
- 跨公司共用專案或分類
- 統計「全部公司」合計
